# 0052. Service worker generated with Workbox after the build and the search index

- **Status:** Accepted; implements [0033](0033-pwa-offline-texts.md)
- **Date:** 2026-11-24
- **Requirements:** RF-53, RF-54, RT-40

## Context

RF-54 asks that, after the first visit, the structure, texts, records and **search** work without a connection. Audio and video still need one ([ADR 0033](0033-pwa-offline-texts.md)). The search index is written by Pagefind **after** `astro build`. The technical requirements named `@vite-pwa/astro`, which generates the service worker during `astro build`, before that index exists. It would also bring a set of early-version (0.0.x) packages.

## Decision

- **Workbox, as a build step.** `workbox-build` generates `sw.js` as the last step of `npm run build`: `astro build`, then Pagefind, then `scripts/pwa/service-worker.ts`. Its options are in `scripts/lib/service-worker.ts`, which is unit-tested.
- **Precached on the first visit:**
  - every page: sections, texts, records, gallery and video pages;
  - scripts and styles;
  - the whole Pagefind index;
  - the manifest.
  Measured on the real site: 546 files, 5.5 MB before compression (about 2.5 MB transferred).
- **Cached when first seen:** images (stale-while-revalidate, at most 300) and fonts (cache-first).
- **Never cached:** audio, video and the admin. Offline, the player says that a recording needs a connection.
- **Pagefind's `?ts=` cache-busting parameter** is ignored when matching the precache, so the search works offline.
- **Updates** take over at once (`skipWaiting`, `clientsClaim`). The site's scripts load when a page opens, so no open page needs a file the update removes.
- **Manifest** from the UI strings, served at `/manifest.webmanifest` by an endpoint (`src/lib/pwa/manifest.ts`).
- **Icons** from Marcelo's self-portrait in a top hat, the Foundation's logo, generated by `scripts/pwa/icons.ts` from the scan outside the repository. There is a maskable version for Android launchers and an Apple touch icon. They replace Astro's default favicon.
- **Registration** only in a build (`import.meta.env.PROD`), so `astro dev` never caches anything.

## Consequences

- Reading and searching work offline in Chromium, Firefox and WebKit; E2E tests check it by cutting the connection after the first visit.
- A first visit downloads about 2.5 MB in the background, mostly pages. If the archive grows a lot, pages can move from precache to runtime caching.
- The E2E build also has the service worker, so every E2E test runs with it, as visitors do.
- Building needs `tsx`, already a development dependency.

## Rejected alternatives

- **`@vite-pwa/astro`:** its service worker would miss the search index, and it brings early-version dependencies.
- **Caching pages only as they are visited:** pages never opened would not work offline, which RF-54 asks for.
- **A handwritten service worker:** Workbox's precaching, revisioning and expiry are standard, tested code.
